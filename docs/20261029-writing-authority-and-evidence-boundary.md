# 写作主线与证据呈现边界

日期：2026-10-29（Asia/Shanghai）。范围：第 9、10 步之前补修用户标出的两处问题。沿用[已完成的第 6、7、8 步](20261029-skill-writing-upstream-adaptation.md)和来源清单；两层分别提交。

## 基线与定位

改前独立生成抽样：使用批准的桌面理线材料和“不曾进行效率／电气／承重测试”的编辑记录，实际生成 224 字正文，没有把内部核验记录或免责语写入正文。该案例没有复现坏输出，不能据此声称现行系统每次都会泄漏。

独立契约审阅发现剩余歧义：writing-pipeline 的交付句要求一起交 draft/edit、evidence pointers 和 unresolved inputs，而 write-content 要求仅交文章；copywriting／copy-editing 缺少对共同表达方法的明确归属；anti-slop、quality 和 reader 同时拥有表达判断。此次处理这些可定位的集成缺口。

## 第一层：证据要求先转为主张选择

增加 reader 方法下的 evidence-to-prose 参考，并从事实核验、项目上下文及写作交付接入。先根据证据删减或缩窄主张；核查状态留在已有任务记录。正文只承载影响读者决策、操作、事实解释、归属或必要披露的条件。

兼容性、安全、概念图标签和证据评估报告中的必要不确定性继续保留。只交正文的任务不附核验清单或默认编辑报告；小改动不额外创建台账。

验证：改后独立生成了三份实际文本。理线正文 204 字，保留五项操作且不输出未做效率／电气／承重测试的记录；USB-C 指导保留两个必要规格检查；管理者效果评估保留同期活动与对照不足，直接回答归因问题。评估稿尾句还有可合并的重复限定，作为下一层统一表达方法的复核点；没有把“保留证据边界”误做删除真实不确定性。严格引用及 39 项结构／来源／工作流回归通过。

## 第二层：唯一表达方法

选择 reader-experience-review 为唯一表达方法，并将其扩展为起草及修订时使用的“读者任务 → 有依据的回答 → 必要解释／条件”主线。保留现有技能名称和所有来源身份。

| 材料 | 当前职责 |
|---|---|
| reader-experience-review | 唯一表达判断：措辞、顺序、例子、转场、条件如何进入正文 |
| write-content／improve-content | 任务范围、研究复用、文章或局部修改、交付格式 |
| copywriting／copy-editing 等业务技能 | 真实 offer、读者问题、商业判断与可选诊断输入 |
| fact-checking／quality-scoring | 主张的事实支持、任务完整性和适用 SEO 验收；通过 reader 方法表达修正后的主张 |
| voice 参考 | 真实样本中的语域、术语与作者输入 |
| anti-slop 参考 | 已观察到问题时的诊断例子；没有独立文风、评分或审阅回合 |

根 AGENTS、技能索引和九个常用写作／营销入口已接入同一归属。清除“入口和 reader 共同决定文风”、copy-editing 的清晰度／声线回跳链、句长／连词阈值及 copywriting 的默认注释／备选交付；声线、质量检查与改稿参考的输出也按正文／任务记录分开。邮件人称、篇幅及 CTA 示例按任务选择，不构成另一套表达门槛。

## 实际成稿复核

改后由独立会话读取当前文件并完成四份实际文本：

- 理线正文保持实操顺序，不出现未做效率／电气／承重测试的内部记录。
- 两句效果评估保留 28 天窗口、12% 增长、同期活动和对照不足；不把真实归因限制删掉，未再追加一段重复免责。
- 试用区成稿：“无需信用卡，即可开启 14 天免费试用。试用期间可随时取消。”仅使用已批准 offer，不附注释、备选或核验缺口。
- 厂商核实的维护三句接受原文零修改，保留防液体进入接口的警告，不要求作者再交一版。

测试报告能分别指出表达权威、事实验收与交付归属。整体契约复核又找到索引尾段和 sweep 回跳链的残留，均修正；没有把独立诊断重新变成强制风格轮次。
