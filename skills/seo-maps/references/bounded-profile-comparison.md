# Bounded business profile comparison

Use with [seo-maps](../SKILL.md) for a GBP/local visibility review. Resolve the actual location with CID/place ID and verify the storefront coordinate before a paid grid. A chain needs location-level identity, not name matching alone.

Reuse eligible profile observations. Compare categories, claim status, hours, location-page link and observed reviews with relevant nearby competitors. Prefer the location's page over a stale domain or unrelated homepage, but diagnose the actual mismatch rather than assuming a homepage is always wrong.

Start with a small grid and keyword set adequate to the service area; expand only when it changes the decision and spending is authorized. State coordinate, radius/spacing, keyword, date and returned results coverage.

At each point retain rank when returned, not-found, resultsCount and error separately. A sparse result set does not prove invisibility; failures do not count as absence. Do not assign not-found a measured rank of 21 or blend it into an unlabelled average. Compare only matching grids and coverage.

Prioritize observed profile/identity problems over speculative posting cadence. Review frequency, sentiment patterns and response rates can guide questions, not prove fake reviews or ranking penalties. Do not recommend review gating, fabricated reviews or keyword-stuffed business names.

Deliver profile/location observations, point-level coverage, supported leading actions and missing inputs. Website changes call [seo-local](../../seo-local/SKILL.md); platform operations need their actual connector and authorization.
