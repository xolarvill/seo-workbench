# Source orchestration method adapted to Workbench

This reference retains the source method's industry detection and specialist coverage. [The canonical SEO entrypoint](../SKILL.md) selects current methods; [Workbench operations](workbench-operations.md) supplies the installed execution interfaces. Source IDs, original paths and baseline revisions are recorded in the repository's skill source inventory.

## Select by the site and question

Use observed site signals to choose relevant methods:

| Site signals | Additional useful coverage |
|---|---|
| Pricing, features, integrations, trial/signup | SaaS positioning, feature ownership and conversion paths |
| Address, service area, phone, maps | Local presence, citations, review evidence and location intent |
| Products, collections, cart, product structured data | Product/category indexation, variants, merchant information and ecommerce content |
| Articles, authors, topics and publication dates | Editorial quality, topical coverage, authorship and internal discovery |
| Case studies, industries, client work | Service positioning, proof and lead-generation journeys |

Mixed business types may need several methods. Record the signals and working interpretation; confirm with project context when the classification affects a material recommendation.

## Compose the coverage

Consult the [skill index](../../README.md) and read the canonical bodies needed now. Useful audit lenses include technical collection/indexation, on-page metadata and internal links, content and E-E-A-T, schema, sitemaps, images, field performance, rendered usability, AI search visibility, local/maps, backlink evidence, content clusters, search experience, ecommerce and comparable baseline drift.

Optional API evidence belongs in the audit only when configured and useful to its question. Read `seo-google` for first-party Google sources, `backlinks` for provider-scoped links, and `seo-dataforseo` for paid or connector-backed enrichment. A method name does not establish that a connector, executor or specialist agent exists. Follow current delegation authorization if parallel work is warranted.

## Combine findings

Keep observed failures separate from uncollected coverage. Prioritize by demonstrated impact on the requested goal, affected routes/templates, available search/business context and effort. Do not turn incomplete collection into missing-metadata findings or sum vendor scores into a new health score.

Use comparable snapshots for drift; source and identity must match before describing regression. Use CrUX for performance verdicts, Lighthouse for diagnostics, GSC for observed search data and indexed-version inspection, and GA4 for its own channel/event evidence. A single tool cannot substitute for these distinct sources.

Retain evidence pointers, decisions and remaining coverage in the task report. Report formats follow the existing project workflow; weekly presentation generation has its own readiness gate.
