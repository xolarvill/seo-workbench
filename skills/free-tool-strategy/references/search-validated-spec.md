# Search-validated tool specification

Use when choosing a tool to build for organic acquisition. Reuse [free-tool-strategy](../SKILL.md) for business fit, resources and maintenance.

Read the buyer's job, adjacent manual calculations/documents/checks and existing tools. Discover tool candidates from customer language, relevant competitor pages and observed queries; remove existing tools unless improving one is the task.

Compare a bounded candidate set on audience fit, observed demand (or unknown), whether results serve tools or articles, competing capabilities, a useful difference and build/maintenance burden. A crowded result set needs a concrete advantage, not another identical calculator. Missing volume and KD remain unknown according to source semantics, not proof of no demand or easy competition.

Read the decisive competing tools. Choose an option only when its value and feasible difference are supported. Give rejected options and reasons; no fixed score or minimum volume decides automatically.

For the chosen tool specify: intended URL and query family; user job; inputs, units and validation; outputs with an example; data/formula source and usage rights; distinguishing capability; product next step; mobile/accessibility requirements; API cost per use and limits when applicable; maintenance owner/questions; and useful success events. Do not invent data, calculations or economics; unresolved dependencies remain explicit.

Use observed linking/resource pages to identify initial promotion prospects through [linkbuilding](../../linkbuilding/SKILL.md). A provider returning no links cannot show that the leader ranks without link influence. A spec does not authorize building, publishing, spending or lead capture beyond the user's request.
