# Cluster strategy review

Read when a proposed cluster needs an ownership and architecture check. Use [topic-cluster-planning](../SKILL.md) as the canonical entrypoint.

## Method

1. Group the actual reader intents and inspect the inventory of existing owners.
2. Check whether the hub explains the shared topic and each spoke completes a distinct task.
3. Review overlap, missing support, contextual link directions and dependencies on research or first-party input.
4. Sequence work by reader/business value and dependencies, keeping updates to existing pages visible alongside proposed new pages.

## Deliverable

Return the hub/spoke ownership map, overlap decisions, linking rationale and production dependencies.
